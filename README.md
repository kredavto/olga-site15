# LUMEN VET — сайт премиальной ветеринарной клиники 24/7

Многостраничный сайт круглосуточной ветеринарной клиники: экстренная помощь,
9 направлений, врачи, прозрачные цены с калькулятором, онлайн-запись, блог и
SEO-структура. Собирается собственным статическим генератором на Node — **без
зависимостей, без сборщиков и без внешних JS-библиотек**.

```bash
npm run build     # собрать сайт в ./dist
npm run preview   # собрать и открыть на http://localhost:4173
```

## Структура проекта

```
src/
  data/       контент: клиника, услуги, врачи, цены, статьи, отзывы, FAQ
  lib/        html-хелперы, иконки, генератор изображений, layout, блоки секций
  pages/      сборка конкретных страниц
  photos/     реальные фотографии (см. src/photos/README.md); пусто — используются плейсхолдеры
  assets/     CSS (6 слоёв) и app.js
build.mjs     генератор: страницы, изображения, sitemap, robots, manifest
dist/         результат сборки (готов к статическому хостингу)
```

Весь текстовый контент лежит в `src/data/*.mjs` — правки контента не требуют
касаться разметки.

## Дизайн-система

- **Палитра**: глубокий сине-зелёный (`#071E21`), медицинский teal (`#0F827E`),
  sage, тёплый бежевый, молочный; акцент — мягкий мятный `#6FE0D0`.
- **Типографика**: Manrope (интерфейс) + Cormorant Garamond (editorial-акценты),
  подключены с `display=swap` и полным системным фолбэком — сайт корректно
  выглядит даже без доступа к Google Fonts.
- **Поверхности**: `data-surface="dark"` переключает семантические CSS-переменные,
  поэтому один и тот же компонент работает на светлом и тёмном фоне.
- Стекло (`backdrop-filter`), мягкие тени, тонкие световые линии, объёмные карточки.

## Motion и интерактив (vanilla JS, ~28 КБ)

Прелоадер со сборкой логотипа из частиц · scroll-reveal и stagger · split-text
заголовок · параллакс · частицы в hero с реакцией на курсор · magnetic-кнопки ·
3D-tilt карточек · световое пятно за курсором · ambient-градиенты · эффект
сканирования на блоке оборудования · индикатор прокрутки · аккордеон · слайдер
историй · masonry-галерея с лайтбоксом · поиск и фильтры по прайсу · калькулятор
стоимости · мастер онлайн-записи · маска телефона и валидация форм.

**Деградация на слабых устройствах** (`prefers-reduced-motion`, `saveData`,
`deviceMemory ≤ 4`, `hardwareConcurrency ≤ 4`, 2G, узкий экран): число частиц
снижается, связи между ними, tilt, magnetic и параллакс отключаются;
при `prefers-reduced-motion: reduce` анимации выключаются полностью.

## Производительность

| Ресурс | Размер | gzip |
|---|---|---|
| CSS | ~69 КБ | ~14 КБ |
| JS | ~28 КБ | ~8 КБ |
| HTML (главная) | ~117 КБ | ~24 КБ |
| Все изображения (59 SVG) | ~253 КБ | — |

Нет внешних скриптов и шрифтовых блокировок рендера: CSS шрифтов грузится
неблокирующе, `app.js` — с `defer`, у всех изображений заданы `width`/`height`
(нет layout shift) и `loading="lazy"` кроме первого экрана.

## SEO

- Отдельная страница на каждую услугу, врача и статью, ЧПУ-адреса.
- Schema.org: `VeterinaryCare` / `LocalBusiness` (с гео, графиком 24/7 и рейтингом),
  `MedicalProcedure`, `Service`, `Physician`, `BlogPosting`, `FAQPage`,
  `BreadcrumbList`, `OfferCatalog`, `ReserveAction`, `WebSite`.
- Корректная иерархия H1–H3, ровно один `h1` на страницу.
- `title` ≤ 70 символов, `description` 70–320 символов, canonical, Open Graph и
  Twitter Card с индивидуальной OG-картинкой для каждой страницы.

## Доступность

- Контраст текста ≥ 4.5:1 на светлых и тёмных поверхностях (проверено).
- Полная навигация с клавиатуры, видимые focus-состояния, skip-link.
- `aria-expanded` / `aria-controls` у аккордеона, меню и мастера записи.
- Alt у всех изображений, подписи и сообщения об ошибках у всех полей форм.
- Уважается `prefers-reduced-motion`.

## Карта и маршрут

Карта нарисована как SVG в стилистике сайта (без внешних API и ключей), а кнопки
«Построить маршрут» ведут в Яндекс.Карты, Google Maps и 2ГИС по координатам
клиники. Чтобы подключить настоящую интерактивную карту, замените компонент
`vmap()` в `src/lib/blocks.mjs` на нужный виджет — разметка и стили контейнера
останутся прежними.

## Что нужно заменить перед публикацией

Проект — готовый фронтенд с демонстрационным наполнением:

1. **Фотографии.** Пока все изображения — сгенерированные SVG-плейсхолдеры
   (мягкие градиентные композиции в фирменной палитре). Чтобы поставить реальные
   снимки, **править код не нужно**: положите файлы в `src/photos/` с именем,
   равным ключу изображения (`hero-main.jpg`, `doc-orlova.webp` и так далее), и
   запустите `npm run build`. Сборка сама подставит фото вместо плейсхолдера,
   соберёт `<picture>` с AVIF/WebP, если положить несколько форматов, и прочитает
   реальные `width`/`height` из файла. Ключи без файла остаются с плейсхолдером,
   поэтому фотографии можно добавлять по одной.
   Полный список из 59 слотов с размерами и описанием кадров —
   в [`src/photos/README.md`](src/photos/README.md).
2. **Контакты и реквизиты.** `src/data/clinic.mjs`: название, телефон, адрес,
   координаты, ссылки на соцсети; `src/data/content.mjs` → `documents`: лицензии.
3. **Цены и врачи.** `src/data/prices.mjs`, `src/data/doctors.mjs`.
4. **Отзывы.** `src/data/content.mjs` → `reviews`: заменить на реальные и добавить
   ссылки на внешние площадки в разделе `/reviews/`.
5. **Обработчик форм.** Формы («Задать вопрос», онлайн-запись, отзыв) сейчас
   валидируются на клиенте и показывают успешное состояние без отправки.
   Подключите ваш backend/CRM в блоке `forms()` в `src/assets/app.js`.
6. **Домен.** Базовый адрес берётся из переменной окружения `SITE_URL`; если она
   не задана, на Vercel подставляется production-домен проекта, а локально —
   запасное значение из `src/data/clinic.mjs`. От него строятся canonical,
   Open Graph, JSON-LD и `sitemap.xml`, поэтому при подключении собственного
   домена задайте `SITE_URL=https://ваш-домен` в переменных окружения проекта.

Медицинские тексты написаны как демонстрационный контент и перед публикацией
должны быть проверены практикующим ветеринарным врачом.

## Деплой

`dist/` — обычная статика, подходит для любого хостинга.

**Vercel** (основной деплой): настройки лежат в `vercel.json` — сборка
`npm run build`, вывод `dist`, установка зависимостей пропускается. При импорте
репозитория ничего настраивать вручную не нужно.

**GitHub Pages**: workflow `.github/workflows/pages.yml` собирает сайт при пуше
в `main`.

Каталог `dist/` закоммичен как снимок для быстрого просмотра файлов в
репозитории; на хостинге он всегда пересобирается из исходников, поэтому при
локальной сборке без `SITE_URL` он может отличаться значением базового адреса.
